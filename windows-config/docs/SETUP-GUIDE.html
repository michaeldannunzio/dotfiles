Runbook / Z690 desktop

Windows config repository

Two declarative layers: the Windows host, and WSL2 running the same Nix configuration as the MacBook.

Folder structure

This layer lives in windows-config/ of the dotfiles repository. Each file names its own repo path in its header.

windows-config/
  bootstrap.ps1
  configuration.dsc.yaml
  .gitignore
  debloat/Debloat.ps1
  scripts/Export-Baseline.ps1
  scripts/Link-Dotfiles.ps1
  dotfiles/Microsoft.PowerShell_profile.ps1
  dotfiles/windows-terminal-settings.json
  dotfiles/gitconfig
  dotfiles/ssh-config
  wsl/Install-WSL.ps1
  wsl/wsl-bootstrap.sh
  docs/SETUP-GUIDE.html

How the two layers split

Nix does not run natively on Windows. So the machine is managed by two tools, not one.

The part you already built

Your nix-config flake has a homeConfigurations."server" output. WSL2 is Linux, so it uses that output unchanged. Your shell, git, neovim, direnv, and aliases become identical on the Mac and the PC. The Fedora dual boot uses the same output later.

01

Record the machine first

This is the Windows version of the defaults read diff you run on the Mac. Run it now, and again after every stage.

.\bootstrap.ps1 -Stage Baseline

It writes four files to %USERPROFILE%\baseline: your winget package list, your Store app list, the Explorer registry branch, and your startup entries. Compare two runs to find the exact key that a setting changed.

02

Remove the apps

Removal comes before installation. If you install first, you can delete something you wanted.

powershell.exe
.\bootstrap.ps1 -Stage Debloat

Read before you run

  • Use powershell.exe 5.1. App removal and restore points need modules that PowerShell 7 does not have.
  • Do not start it from Windows Terminal if you plan to remove Windows Terminal.
  • Edit $AppsToRemove in the script to match the choices you made the first time. Get the exact names from your stage 01 appx file.
  • Keep Microsoft Store, Windows Terminal, and Edge. winget needs the Store framework.
03

Install apps and apply settings

One YAML file holds every app and every registry setting. The command is idempotent: run it as often as you like, and it changes only what does not match.

pwsh
.\bootstrap.ps1 -Stage Configure

The stage installs the two DSC modules, validates the file, shows you the plan, then applies it. To see the plan alone:

winget configure show -f configuration.dsc.yaml

Confirm the package IDs

Package IDs change over time. Before the first run, check each one:

winget search "NordVPN"
winget search "Google Drive"

If winget configure is not recognized, update winget from the Microsoft Store, then run winget settings --enable Configuration.

04

Link the dotfiles

Stage 03 turns on Developer Mode, which lets a normal user create symbolic links. Now point Windows at the files in the repo.

.\bootstrap.ps1 -Stage Dotfiles
Repo fileLinked to
Microsoft.PowerShell_profile.ps1Documents\PowerShell\
windows-terminal-settings.jsonTerminal LocalState
gitconfig%USERPROFILE%\.gitconfig
ssh-config%USERPROFILE%\.ssh\config

Any existing file is renamed to .bak first. Use -WhatIf to see the plan without changing anything.

Keys stay out of the repo

The script links the SSH config only. Private keys stay in %USERPROFILE%\.ssh. Load them into the Windows agent once:

Get-Service ssh-agent | Set-Service -StartupType Automatic
Start-Service ssh-agent
ssh-add $env:USERPROFILE\.ssh\id_ed25519
05

Install WSL2

.\bootstrap.ps1 -Stage WSL

With no distribution name, the script lists what is available. Pick one, then:

.\wsl\Install-WSL.ps1 -Distro <Name>

Open the distribution once to create your Linux user. Then restart Windows.

06

Apply your Nix configuration inside WSL

This is where the two repositories meet.

bash wsl/wsl-bootstrap.sh

The script does four things: it turns on systemd in /etc/wsl.conf, installs Nix, clones your nix-config repo, and applies the server home-manager output.

The systemd restart

The Nix daemon needs systemd. The first run edits /etc/wsl.conf and stops. Run wsl --shutdown in PowerShell, reopen WSL, then run the script again.

Two rules that decide your performance

  • Keep all code in the Linux $HOME. Never in /mnt/c. Metadata operations across the 9p bridge are roughly sixty times slower, and metadata is what git status and npm install do all day.
  • Toolchains come from nix-config/templates/devshell/flake.nix per project, not from a global install.

Before you commit

  1. Replace CHANGE ME in dotfiles/gitconfig and dotfiles/ssh-config.
  2. Replace CHANGE_ME in wsl/wsl-bootstrap.sh with your nix-config repository URL.
  3. Replace CHANGE_ME in the WSL profile path in windows-terminal-settings.json.
  4. Confirm the .gitignore blocks your key files.
