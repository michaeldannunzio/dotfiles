Nix Setup Guide

MacBook Pro M2, plus Linux desktops, remote servers, and a work Mac.

Repository layout

This configuration lives in nix-config/ of the dotfiles repository. Clone it, or symlink that directory to ~/.config/nix-config:

nix-config/
  flake.nix
  .gitignore
  hosts/mbp-personal/default.nix
  hosts/mbp-work/default.nix
  hosts/linux-desktop/default.nix
  hosts/linux-desktop/hardware-configuration.nix   (generated on the machine)
  modules/darwin/defaults.nix
  modules/darwin/homebrew.nix
  home/core.nix
  home/darwin.nix
  home/linux.nix
  templates/devshell/flake.nix
  templates/devshell/.envrc
  docs/SETUP-GUIDE.html

Before you start

Capture your current macOS settings first. You changed them by hand after the reset. If you do not record them now, you must find them again later.

defaults read > ~/baseline-defaults.txt
defaults -currentHost read > ~/baseline-currenthost.txt

Nix creates a /nix APFS volume. Removal is difficult. Decide now if you accept that.

Step 1. Install the prerequisites

  1. Install the Xcode command line tools: 
    xcode-select --install
  2. Install Nix. The nix-darwin project recommends the Lix installer, because it includes an uninstaller. See lix.systems/install.
  3. Install Homebrew. Nix does not package macOS GUI apps well, so Homebrew supplies the casks: 
    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
  4. Open a new terminal window, so the shell finds the new commands.

Step 2. Prepare the repository

  1. Point ~/.config/nix-config at the nix-config/ directory of this repository.
  2. Edit the three lines at the top of flake.nix: 
    username = "CHANGE_ME";
fullName = "CHANGE ME";
email   = "changeme@example.com";
  3. Set the hostname of the Mac, so it matches the configuration name: 
    sudo scutil --set LocalHostName mbp-personal
  4. Start the git history. Nix flakes only read files that git tracks: 
    cd ~/.config/nix-config
git init
git add -A
git commit -m "initial config"

Step 3. First build

cd ~/.config/nix-config
sudo nix run nix-darwin/nix-darwin-26.05#darwin-rebuild -- \
  switch --flake .#mbp-personal

After this build, all later changes use the short command:

sudo darwin-rebuild switch --flake ~/.config/nix-config#mbp-personal

The first build fails if homebrew.enable is true and Homebrew is absent. Install Homebrew first, or comment out the import of modules/darwin/homebrew.nix.

Step 5. Per project toolchains

Do not install Node, Python, Go, or Rust into your user profile. Each project carries its own versions.

  1. Copy templates/devshell/flake.nix and templates/devshell/.envrc into the project.
  2. Delete the language sections you do not need.
  3. Run direnv allow once.

direnv now loads the correct tools when you enter the directory, and unloads them when you leave.

Swift and iOS

Xcode is the exception. Nix cannot supply it. Install Xcode from the App Store, then run:

sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -license accept

Step 6. Add the other machines

Work Mac

  1. Set its hostname to mbp-work.
  2. Clone the repo and build .#mbp-work.

Linux desktop

  1. On the machine, run: 
    sudo nixos-generate-config --show-hardware-config \
  > hosts/linux-desktop/hardware-configuration.nix
  2. Remove the comment markers from the nixosConfigurations block in flake.nix.
  3. Build with sudo nixos-rebuild switch --flake .#linux-desktop.

Remote servers

Servers get user level configuration only. No root is needed.

nix run home-manager/release-26.05 -- switch --flake .#server

Secrets

Never write a plain secret into a Nix file. Nix copies flake files into the world readable store. The sops-nix input is already present in flake.nix. Use it with an age key when you are ready.

Order of work

  1. Get the Mac to build and switch with a small configuration.
  2. Add your macOS settings, one at a time, and confirm each one with the defaults read diff.
  3. Add the GUI apps as casks.
  4. Move your shell and git configuration into home/core.nix.
  5. Add devshells to your projects.
  6. Only then add the other machines.
